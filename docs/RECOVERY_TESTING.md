# Recovery fault tests

Run `cargo test -p speedrun-cli recovery::tests` for focused coverage. Before a commit, also run `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`, and `cargo test --all`.

After `cargo build`, run `python3 scripts/recovery-smoke.py` for a real CLI/daemon roundtrip in temporary directories. It starts a signed run, stops its daemon, queues concurrent Claude hooks while creating a bundle, restores into a new directory, and flushes twice. It checks the snapshot cutoff, unchanged source queue, expired-lease recovery, exactly one stored event per restored request, and the restored signature chain. An optional argument selects a directory containing the two compiled binaries.

The populated fault fixture reaches 20 create checkpoints: destination staging directory, database snapshot, six optional-file copy positions, one disclosure file and its completed directory, outbox snapshot, four spool-file copies, completed spool, manifest, validation, ready to publish, and published. It reaches 20 restore checkpoints: source validation, staging directory, 13 file copies, manifest copy, copy validation, manifest removal, ready to publish, and published. Each reached point is exercised with an injected error and with SIGKILL in a separate process. During the SIGKILL matrix, a writer repeatedly invokes the real Claude hook handler. Tests check source/bundle integrity, no overwrite, and retry. Before publication the requested destination remains absent; after publication it is complete. An interrupted process can leave a private `.speedrun-recovery-*` sibling directory, which can be removed after confirming no recovery process is using it.

The queue tests use the production encrypted enqueue path at checkpoints and with a writer running across the SQLite snapshot. A separate subprocess invokes the Claude hook handler repeatedly while recovery runs. An enqueue committed before the outbox snapshot is included; one committed afterward remains in the source but need not appear in the bundle. If the spool directory did not exist when create checked for it, that check is the cutoff: a later first enqueue remains in the source and is not included. Validation authenticates the snapshotted encrypted queue against its copied key.

SIGKILL tests process interruption, not sudden power loss or storage-controller behavior. Recovery syncs staged files and directories before an atomic no-replace rename, then syncs the parent directory. If the rename succeeds but the parent sync fails, the command can report an error even though a complete destination exists; inspect that destination before retrying. The tests do not simulate a power cut or assert filesystem-specific durability guarantees.
