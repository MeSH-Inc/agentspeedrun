# Live display contract

For anything that shows runs live: desktop widgets, picture-in-picture,
menu-bar items, phones, TV dashboards. Displays render one JSON shape,
`LiveSnapshot`, and tick its clocks locally. They never compute run state.

- **Types:** `LiveSnapshot` in `schema/protocol.schema.json`. Generate TS or Swift types from it, e.g. `npx json-schema-to-typescript` on `$defs`. Rust source: `crates/speedrun-core/src/live.rs`.
- **Example data:** `schema/examples/live-snapshot.json`. One run with two agents working, one split ahead of PB, one agent-proposed milestone. Generated by a test, so it always matches the real types. Use it for mocks and stories.

## Shape

```
LiveSnapshot { as_of, cursor, runs: LiveRun[] }

LiveRun {
  run_id, project_id, project_name, category {id, version, name},
  status: running | paused | completed | abandoned,
  started_at, finished_at, last_event_at,
  timing   {wall_ms, timed_ms, agent_ms, human_ms}   // at as_of
  running  {wall, timed, agent, human, human_stops_at} // which clocks advance
  active_agents, prompt_count,
  progress {counted, total},                          // category milestones
  milestones: LiveMilestone[],                        // category first, in order
  pb: {run_id, project_name, timing} | null           // best earlier completed run
}

LiveMilestone {
  milestone_id, key, title, origin: predefined | user | agent_generated,
  state: proposed | accepted | rejected | reached | verified,
  trust, required_trust, counts,
  split, pb_split, delta_ms                           // delta < 0 = ahead of PB
}
```

Clocks:
- `wall_ms` is real time since the first prompt.
- `timed_ms` is real time minus pauses. It is the primary clock: PBs and deltas use it.
- `agent_ms` is time at least one agent was working.
- `human_ms` is time between agent turns, with each gap capped at 15 min.

## Ticking locally

Do not poll for time. Each frame, compute every clock from the latest snapshot:

```ts
function timingAt(run: LiveRun, asOf: Date, now: Date): Timing {
  const dt = Math.max(0, now.getTime() - asOf.getTime());
  const r = run.running;
  const humanEnd = r.human_stops_at ? Math.min(now.getTime(), Date.parse(r.human_stops_at)) : now.getTime();
  return {
    wall_ms:  run.timing.wall_ms  + (r.wall  ? dt : 0),
    timed_ms: run.timing.timed_ms + (r.timed ? dt : 0),
    agent_ms: run.timing.agent_ms + (r.agent ? dt : 0),
    human_ms: run.timing.human_ms + (r.human ? Math.max(0, humanEnd - asOf.getTime()) : 0),
  };
}
```

This is `LiveRun::timing_at` in Rust, and a test checks that it matches a
full recompute. Clock skew between display and daemon shifts every clock by
the same constant. To correct for it, compare `as_of` with your local clock
when a snapshot arrives and adjust.

## Getting snapshots (desktop: local daemon)

| Route | Use |
|---|---|
| `GET /v1/live?since_hours=168` | One snapshot. |
| `GET /v1/live/stream?since_hours=168` | Server-sent events. Each `snapshot` event is a complete `LiveSnapshot` (`id` = cursor), computed on connect, after changes, and on a 60 s refresh interval. Slow readers may skip intermediate snapshots. Keep-alive comments in between. |

- **Replace, don't merge.** Every message is complete. Compare cursors only within the same source identity and generation; reset on a new generation. Within that scope, drop lower cursors but accept equal cursors because verification status and clocks can change without a new event.
- **Reconnect freely.** There is no resume protocol; the first message after reconnecting is a full snapshot.
- **Window.** Runs appear if they are the newest, unclosed run of their project with activity within `since_hours`. Unfinished runs sort first.

Connected streams share one producer, including streams with different windows.
Each connection filters the shared snapshot for its own window. The producer
retires after its last subscriber disconnects; there is no idle snapshot cache.
GET requests remain independent fresh reads.

Address: `http://127.0.0.1:7477` (`SPEEDRUN_ADDR`).

### Auth

- Use the **display token**: `$SPEEDRUN_HOME/display-token`, or `speedrun display`. It is read-only and only works on `/v1/live*` and `/v1/categories`, which do not contain prompt text. Snapshots still expose project names, milestone titles and run activity, so treat the display token as access to that information.
- Send it as `Authorization: Bearer <token>`, or as `?token=<token>` because browser `EventSource` cannot set headers.
- The full token in `token` also works, but never give it to a display.

### Browser pages (Document Picture-in-Picture, web widgets)

Start the daemon with an origin allowlist:

```bash
SPEEDRUN_CORS_ORIGINS=http://localhost:5173,https://widget.example speedrund
```

Only GET on the display routes gets CORS headers.

## Phones and other machines (planned)

The daemon only listens on loopback by design. Phones will receive the
**same `LiveSnapshot`** from the cloud sync service, which recomputes it
from synced events. It will not come from the daemon over the LAN.
Displays should treat the transport as swappable:

```
source = local SSE | cloud SSE/WebSocket | static example file
render(snapshot) + timingAt(...) per frame
```

Native widgets that cannot hold a connection (iOS WidgetKit, Android
Glance) get a snapshot from a push or background refresh. With `running`
and `as_of` they can use the platform's own timer views (e.g. SwiftUI
`Text(timerInterval:)`) for clocks that are running.

## Reference client

`speedrun watch` is a terminal implementation of this contract: it follows
the stream, ignores stale cursors, ticks with `timing_at` and reconnects.
`speedrun watch --once` prints one frame.

## Compatibility

New fields may appear in any version, so ignore unknown fields. Removing or
renaming a field, or changing its meaning, goes through a protocol version
bump.
