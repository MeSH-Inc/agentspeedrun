# v0.3.3 preview candidate

This candidate includes discoverable help for the `hook` and `ingest` integration
commands. Help works at command and event positions; malformed host arguments
retain their always-zero behavior. All binaries and adapters share version
`0.3.3`.

The repository also includes opt-in live-host verification for real model turns,
status and milestone-proposal tool results, signed events, and turn closure.
These checks do not count provider errors or missing authentication as success.

Guided setup now tells VS Code users to select **Local** in the agent harness
picker. An actual VS Code 1.144.0 Local session captured a prompt, invoked status
and milestone-proposal tools, and closed a signed turn. The newer Copilot SDK
Agent Host mode did not capture a prompt in the tested configuration; its tool
behavior remains unverified. See [VS Code live verification](../VS_CODE_LIVE_VERIFICATION.md).

## Installation after publication

```sh
curl -fsSL https://raw.githubusercontent.com/MeSH-Inc/agentspeedrun/v0.3.3/install.sh | SPEEDRUN_VERSION=v0.3.3 SPEEDRUN_SKIP_ATTESTATION=1 sh
```

This candidate is not published yet. Locally built assets have checksums but no
provenance attestations; the command skips only attestation verification. Use
the matching prerelease VSIX for VS Code. Re-run `speedrun setup` for the chosen
host and restart it after upgrading embedded adapters.

## Compatibility and coverage

OpenCode v2 is supported; v1 requires the earlier adapter. Active-turn state is
not transferred through OpenCode plugin hot reload. Zed native agent prompt
capture is unsupported. Native Intel hardware is unavailable; distinguish
emulation and native AMD checks from Intel coverage. Agent-led first-use
sessions do not establish unassisted human usability.

The candidate's accompanying `VERIFICATION.md` records exact binaries, packaged
checks and live-host coverage. See [host verification](../HOST_VERIFICATION.md)
and [first-use testing](../FIRST_USE_TESTING.md) for the broader evidence and
its limits.
